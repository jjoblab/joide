Refonte IA — aperçu des écrans

⚠ Aperçu d'illustration — les modèles, prix, compteurs et contenus montrés ici sont des exemples de maquette. Dans l'application, tout vient du fournisseur (catalogue vivant), de l'utilisateur ou d'une constante documentée : rien d'inventé ne s'affichera comme réel. Jetons : colors.xml clair + sombre.

Plan de la refonte (résumé)

Lot 0 (livré) — séparation Assistant (accueil, sans outils, conversations persistées JSON dans filesDir/assistant/ derrière ConversationStore) / Agent (tiroir droit, puces de contexte réelles via AgentContext). Lot 1 — ai/json/Json (codec complet), SseParser, réécriture d'HttpLlmTransport (outils fragmentés par index, annulation, reprises), LlmError typé + rédaction des secrets, tests sur serveur HTTP JDK. Lot 2 — ProviderRegistry : OpenRouter, OpenAI, Anthropic, Gemini, passerelle personnalisable ; migration passerelle→custom, suppression des identifiants fictifs. Lot 3 — agent plus sûr : outils un fichier par outil + schémas JSON, modifier_fichier par remplacement ciblé, garde-fous de chemins, diff réel à l'approbation, points de contrôle (annulation de tour), AGENTS.md enfin lu. Lot 4 — ConversationStore généralisé (double contenu transcript/historique, atomique), liste assistant et agent, AiSessionViewModel (survit rotation/tiroir/onglet). Lot 5 — rendu Markdown streaming-safe + ResponseInterpreter (blocs code avec cible, diffs applicables, réflexion repliable, chips de suivi), cartes d'outils vraies. Lot 6 — design du chat (composer extensible, Stop, jauge de contexte, états vides, accessibilité). Lot 7 — Réglages IA en hub + sous-pages, matrice de câblage complète. Lot 8 — intégrations atelier (ouvrir fichier à une ligne, rafraîchissement après mutation, build du mode actif). Lot 9 — qualité, ADR, docs, contrôles automatiques (API 28, câblage, aucune donnée factice).

1 · Assistant (accueil)

Écran plein avec bouton retour. Liste des conversations (titre dérivé du premier message, date relative, compte de messages — persistées dans filesDir/assistant/, un JSON par conversation, écriture atomique). Conversation vide : suggestions de départ qui remplissent le champ sans envoyer. Conversation riche : réponse structurée (titres, liste, tableau, bloc de code coloré avec cible, carte diff, bloc Réflexion repliable, chips de suivi) — un seul chemin de rendu partagé avec l'agent.

2 · Agent du projet (tiroir droit de l'atelier)

Panneau étroit (min(420 dp, écran − 56 dp)) : en-tête compact (pastille IA, « Agent · nom », pills modèle et permission, ⋯), puces de contexte à valeurs réelles (fichier ouvert, problèmes du dernier build, sélection — bascule on/off, jointes au prochain message), ligne d'état au-dessus de la saisie, groupe d'actions repliable avec compteurs issus du diff réel, carte de permission intégrée au transcript (diff avant/après), bloc « Appliquer » passant par la porte, bouton Stop, jauge de contexte.

3 · Sélecteur de modèle (bottom sheet)

Ouvert depuis la pill modèle. Recherche, filtres, favoris, récents ; badges Gratuit / Outils / Raisonnement / Vision ; contexte et prix uniquement s'ils sont connus (catalogue du fournisseur — exemple d'illustration ci-dessous). Un modèle sans support d'outils ne peut servir l'agent : indiqué, avec proposition de repli.

4 · Réglages IA (hub + sous-pages)

La page unique actuelle devient un hub (cartes Material 3, une icône par ligne, état résumé en sous-titre — mêmes composants que le hub Paramètres existant) vers : Fournisseurs · Modèles · Comportement · Permissions et sécurité · Outils et connexions · Utilisation et coûts · Données · Activer/désactiver l'IA. Chaque réglage a un lecteur réel (matrice de câblage, test automatisé) ; un réglage sans effet est retiré ou dit « à venir ».

5 · États honnêtes (aucune donnée factice)

Chaque cause a son message et ses actions. Sans clé : carte explicite avec « Configurer un fournisseur ». Chargement, hors-ligne et troncatures se disent, jamais ne se déguisent.
